# Roadmap

**This roadmap is obsolete and was replaced by the user-journey-based roadmap
in the Architecture and Design Document.**

This roadmap is defined in terms of the sequence capabilities presented
to users over time. These are intended to provide some level of visible
progress and opportunity to influence development to each user type
across the project, within technical constraints.

The roadmap is first presented in the style of an agile or product
roadmap and then a more detailed prediction of the order of
functionality and its mapping to releases.

The user types are:

- Non-expert user
- Service manager
- Data supplier – could be commercial or non-commercial
- Expert users:
  - Data analyser (eg, ‘Remote Sensing Team’ from ITT use cases)
  - Data producer (produces data, QA results or similar in the platform)
  - Application developer

| Mid-March / MS1  | α2              | A few users can find limited data from two different sources (CEDA and Element84 in AWS) by browsing a catalogue. They can process, retrieve and view very limited resources in a pre-determined way and can access some form of workspace storage.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| End April / MS2a | α3              | A wider range users can access a wider range of resources, can search a catalogue, and can execute workflows in a basic way. CEDA's STAC Catalog is harvested and available in the EODH catalogue and harvesting other upstream STAC catalogues is possible.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| End May / MS2b   | MVP/β           | The catalogue is enhanced with item-level catalogue search and more STAC search APIs and a catalogue UI mock-up for further development is agreed. Users can store their own data in the platform using workspaces and notebooks and to some extent workflows can use their workspace storage. Sentinel 2 ARD data is available with WCS and WM(T)S. A prototype design for 'basic' web presence pages is implemented. Browser-based login and session management exists but services are not yet protected behind non-trivial authorization.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Mid-July         | Pre-prototype   | Catalogue users can make their entries private, view crude workflow catalogue entries and see some of the catalogue's hierarchical structure through nested STAC Catalogs. The first parts of the EODH-customized catalogue interface begin to appear, following the mock-up agreed previously. Workflows can create catalogue entries, can be exposed as user services, and can be triggered on data arrival or on a schedule. Users can publish data publicly from workspaces. For public datasets using GeoTIFF or Zarr, WCS and, for at least some high-priority datasets, WM(T)S support is available. The adaptors' concept, functional scope and interfaces are clarified, with a proof-of-concept adaptor fetching some data from at least one commercial provider. The web design for 'basic' pages is iterated on, and a mock-up for Workspace/Project UI pages agreed (dependent on customer approval). API Token-based API access for the workflow APIs and workspace storage is possible. |
| End Aug / MS3    | Prototype EODHP | Workflows can produce annotations and these can be stored in an annotations service. The catalogue can display commercial pricing, perform facetted search and filtering, and expose metadata for non-spatiotemporal data in a more natural and standards-based way (eg, with OGC Records API). Users can define their own notebook environments as Docker images. For public datasets using supported NetCDF formats, WCS and, for at least some high-priority datasets, WM(T)S support is available. Acceptance of open licence requirements can be enforced. Data stream data can be used with OGC services through adaptors. Users can use the web UI to manage their Workspace/Project (store list, API token management, machine user management) using a UI following the agreed mock-up from the previous release, and a mock-up of the remaining web design is agreed, including accounting, billing and account management (dependent on customer approval). Logging has been centralised.   |
| End Nov / MS4    | Pre-production  | The catalogue interface allows for search and display with annotations, particularly QA results, and can show all types of non-STAC catalogue entries. It also has an integrated map view (subject to the earlier mock-up of the catalogue UI). Provenance information can be collected from workflows and workflow execution is better managed (for example, with queuing, prioritisation and/or auto-scaling for load management). Commercial licences are enforced during data access, requiring a user to agree to pay and/or obtain their own licence, and at least some commercial data is fully integrated. Past resource use and associated costs are visible. WM(T)S support is available for any remaining high-priority datasets. Scoped API tokens and more fine-grained catalogue, data and workflow access control is possible, and technical aspects of Edugain integration are completed. Users can self-register.                                                                     |
| End Feb / MS5    | Production      | The full planned commercial data catalogue is integrated and available to users/applications. Costing of proposed use of the platform is possible. More advanced search features like semantic search are present. The platform is more productionized - more scalable, more reliable, has a disaster recovery plan, has rate-limiting, is more observable, etc. Incremental upstream STAC harvesting is possible, allowing the platform to stay synchronized efficiently (subject to data stream support). WCS is supported for private data. Cost predictions can be viewed and invoices can be generated. Any remaining commercial data is fully integrated.                                                                                                                                                                                                                                                                                                                                        |
